## 发布 CI 兼容修复（2026-09-26）

首轮远端 [CI](https://github.com/koocmitwho/video-operation-review/actions/runs/36223015593) 中 Ubuntu 的 Python 3.10/3.12 两组通过；Windows 两组因 FFmpeg 9.0.2 移除 `-filter_script:v`，以及测试未规范化临时目录 8.3 短路径而失败。失败记录保留，没有跳过失败测试。

修复后按 FFmpeg 实际帮助输出选择旧文件滤镜参数或 `-/filter:v`；表达式仍放在文件中。兼容测试模拟两代接口并用本机真实解码器核对像素，完整 CI 会使用各平台实际安装的接口。文件枚举故障注入统一解析路径，且断言指定异常确实命中；真实 8.3 临时目录下已复测通过。

本地 Windows / Python 3.12.10 和 3.10.11 均重新通过 **98 项测试**，分别耗时 101.492 秒和 165.566 秒；两套回归并行运行。新增接口用例已先在旧代码上确认失败，再验证修复。当前提交的远端结果以对应 [工作流运行](https://github.com/koocmitwho/video-operation-review/actions/workflows/tests.yml) 为准。[本地验证摘要](../validation/ci-compatibility-20260926.json) 保留环境和边界。

## 可靠性与性能优化（2026-09-26）

主开发目录合并了原开发版本的两项真实试用修复与发布副本的宿主适配。首轮 97 项测试在 Windows 的 Python 3.12.10 和 3.10.11 下分别全部通过，耗时 105.291 秒和 171.876 秒；两套测试并行运行，耗时不用于版本间性能对比。新增行为均保存了修改前失败用例，随后完成实现和完整回归。

- 角色复核按实际裁剪区域检查：不相交、部分覆盖及小裁剪替代全图被阻断；对应区域、覆盖裁剪、完整原图与合法连续重复帧等价通过。
- 严格与分层模式共用复核调用关联检查，未关联或失效的 actor / asset / frame / hash / trace 不能通过。
- 600 个不连续候选帧成功抽取并逐帧核对像素身份；解析失败、正常提前 EOF、像素不匹配分别诊断。预算恰到末帧时确认真实 EOF 与退出状态，尾部错误仍不通过。
- 字幕区间查询不再因单个重复/倒退 PTS 对每条字幕遍历全片；未知时间附近的长显示区间也与穷举参考一致。缓存算法版本更新，原有来源记录保留，同版本重复导入仍复用。
- 发布差异检查覆盖修改、缺失、多余文件，并拒绝无法完整枚举的目录；Windows junction 和读取失败边界经过测试。检查只读，不自动覆盖目标内容。

60,000 帧 / 1,000 字幕的本地合成微基准：重复 PTS 从 1.695 秒降至 0.091 秒，倒退 PTS 从 1.702 秒降至 0.092 秒；三种基准的 cue 与 warning 内容哈希均保持一致。正常 PTS 从 0.079 秒增至 0.091 秒，存在建索引成本。这个结果不是实际长视频总耗时或固定节省率。

环境：FFmpeg/ffprobe 8.1.2；Python 3.12 对应 NumPy 2.5.1 / Pillow 12.3.0，Python 3.10 对应 NumPy 2.2.6 / Pillow 12.0.0。技能格式和本地 Markdown 链接检查通过。此阶段只完成 Windows/Ubuntu × Python 3.10/3.12 的 CI 配置，随后远端执行与兼容修复见上节。

本轮未重跑历史视频、启动模型视觉会话或运行 OCR/ASR；合成查看登记不计实际看图。数据库 schema 仍为 3。摘要与日志：[reliability-20260926.json](../validation/reliability-20260926.json)、[Python 3.12](../validation/reliability-python312.log)、[Python 3.10](../validation/reliability-python310.log)。以下保留历史验证结果，历史测试数量不表示当前数量。

## 合成教程的实际视觉试用

使用 32 帧、640×360 的合成 UI 教程，包含等待、鼠标/光标变化、单帧菜单、临时输入、取消、重输、应用和文件交接状态。

| 项目 | 严格模式 | 分层模式 |
|---|---:|---:|
| 全帧计算 | 32/32 | 32/32 |
| 实际显示的不同源帧 | 32 | 18 |

| 最终应用值 | 0.02 | 0.02 |

| 完整审阅门禁 | 未通过，素材有缺口 | 未通过，素材有缺口 |

分层试用有 6 个粗审区间、4 个候选操作单元。粗审覆盖 32 帧；操作精审涉及帧 16–24，共 9 帧范围；因步骤仍有未解决项，“已完成精审”范围为 0。候选分组数不是视频真实操作总数。

看图计数曾通过实际工具返回图片与源 PNG/拼图哈希核对。它能证明图片被工具展示，不能证明模型注意力或语义理解无误；脚本中的 independently_verified_visual_frames 仍保持 null。原始会话日志及逐调用收据作为本地开发审计保存，没有包含在公开仓库中，因此本页属于试用结果摘要，读者可以重跑合成测试和自行复核。

此次独立试用在诊断统计时误搜到测试片段；语义主稿在该搜索前已写出，但仍不能把本次称为严格盲测。素材未展示的菜单入口、准确点击、完整文件路径、文件内容同一性和参数单位均被保留为未知。

18 对 32 仅是这一片段的实际源帧查看数量比较，不表示所有视频都能按同一比例减少工作，也不能据此推断总 token、耗时或费用节省。

用户审核中文说明后，使用已安装 DSH 的 headless 模式，实际调用 `deepseek-official` 路由的 `deepseek-flash`。会话标为“部署测试”，只提供当前技能及独立合成录屏；该素材使用与文档示例不同的对象、参数和文件名，生成器、标准答案与测试源码没有提供给审阅模型。未修改现有 profile、未安装插件或依赖。

模型通过 `skill` 加载入口后自行执行环境检查、全帧索引、分层计划、原图/裁剪/拼图导出、真实 `read_image` 看图、登记、操作及疑点记录、审计与导出。试用结果如下：

| 视频 | 32 帧，640×360，8 fps，4 秒，FFV1，无音轨/字幕 |
| 模型与结束状态 | `deepseek-flash`；持久会话 completed，进程退出码 0 |
| 全帧计算与粗审 | 均为 32/32；6 个区间覆盖全片 |
| 实际图片工具调用 | 55 次成功返回图片：32 原图 + 22 裁剪 + 1 拼图 |
| 查看登记 | 64 条：54 原图/裁剪记录 + 10 拼图面板；源帧去重为 32 |

## 已知限制

- 未完成真实用户软件录屏的系统性验收，也没有独立标注的大规模基准。
- 变化分段与有限抽查可能遗漏未抽中的细节；压缩、低清和遮挡会进一步限制识别。
- 首次扫描、源文件哈希、全尺寸差分与恢复回放都有成本，长视频吞吐和内存尚未全面测量。
- 数据库按单写入者使用；多代理应分别产出记录，再串行导入。
- 多视频流、特殊色彩/高位深、动态分辨率以及其他平台组合没有全面覆盖。

后续验收标准见 [layered-acceptance.md](layered-acceptance.md)；脚本约束通过不能被替换成“操作已经完整理解”的结论。
