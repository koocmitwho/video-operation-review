# 0.1.0-rc.1 候选说明

本轮准备首个带固定版本号的本地候选。开发从 `a6dbc742b023ffb42678ea9ee6e83eb8606151e6` 对应交付开始；主开发目录与 Git 发布副本开始时 78 个文件逐字节一致。修改只在主开发目录完成，验证后同步交付文件。

## 行为与兼容性

- `python scripts/review_video.py --version` 输出 `video-operation-review 0.1.0-rc.1`，无需第三方依赖和审阅目录。
- 数据库仍为 schema 3。`valid` 只表示源、证据和记录完整性；`review_complete` 仍要求候选查看及当前门禁完成，不能由 `valid=true` 推出。
- `validate --require-coverage` 的未完成原因改为 `coverage_errors`，不混入 `errors`，未完成仍退出 1。依赖此前 valid 值的调用方应使用退出码与 review_complete。
- 有关联未解决疑点的操作保留精审过程，完成精审计数为 0；报告标题保留原登记状态并提示待核实。
- 恢复目录无需保留历史日志才能继续抽图；失败尝试会结束并保留错误。

## 验证范围

复核既有 8、26、38 秒真实片段，补看同一原视频相邻的 12、8、10 秒窗口；另检查本机文档中的 24.8 秒录屏和项目自建 6 秒合成示例。真实录屏和截图留在本地验证目录，分发包只包含自建示例。

核对以原帧号、PTS、资产 SHA-256 和实际图片工具观察定位，覆盖步骤顺序、对象、临时输入、选中模式、确认/取消、文件交接及可见结果。其他源码或当前模型参数不能补成视频事实。不同代理的画面观察用于内部一致性复核；本轮没有独立人工标准答案，不报告语义准确率。原疑点及补查历史保留。

## 冻结与发布

候选包使用完整交付文件清单和 SHA-256 固定内容；包外清单记录版本、基线提交、各文件哈希及候选压缩包哈希。复制解包后重核清单、版本号、示例相对链接和发布副本差异。

此候选从已冻结的压缩包安装：解出完整的video-operation-review目录，再放入宿主技能发现目录。冻结时远端main仍是发布基线，尚无本候选的远端标签；安装候选时使用包外清单核对字节与`--version`。依赖测试环境写在验证摘要中，requirements.txt继续保留兼容范围，未打包解释器或依赖运行时。

本轮完成本地候选准备。在该次冻结时，Git 提交、标签、推送与 GitHub Release 尚未执行；本轮的本地验证不代表该候选的远端 CI。后续公开候选使用 prerelease，正式稳定版需要补充独立人工标注与用户照做验收。短片结果不代表长视频性能；token 未实测时保持 null。
