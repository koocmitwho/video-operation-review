# 严格模式验收设计

本文保留早期逐状态契约与 31 项回归历史。当前默认分层流程见 [layered-acceptance.md](layered-acceptance.md)。验收使用自建短视频与隔离审阅目录，按可观察行为先写失败用例再实现。

| 场景 | 可控输入与验收结果 |
|---|---|
| 连续重复 | 8 帧无损视频的四段连续状态保留完整索引，映射为 4 个代表 |
| 微小短暂变化 | 单帧 3×3 像素变化及进入/退出状态都有索引和候选原因 |
| 时间与尺寸 | CFR、VFR、非零 PTS 使用原始时间和实际尺寸 |
| 暂停恢复 | 保存已提交范围，恢复后复用差分，新计算与回放分别计数 |
| 失败收尾 | 损坏输入和子进程异常保存失败 attempt、日志及完成前缀 |
| 查看去重 | 同帧原图、裁剪、重复打开保存事件并按源帧去重 |
| 证据引用 | 缺失、替换、待查看及嵌套引用问题返回具体错误 |
| 源身份 | 校验路径和 SHA-256，属性匹配时复用缓存并报告 rehashed |
| 局部补查 | 原始时间范围定位、抽取与裁剪保留帧号和父证据 |
| 可复用交付 | JSON、逐帧 JSONL 与 Markdown 包含步骤、证据、统计和后续范围 |

## 操作遗漏验收

| 场景 | 可观察结果 |
|---|---|
| 低于阈值的单像素状态 | coverage 仍保留，changes 下 audit 能定位待说明状态 |
| 大步骤区间含待说明状态 | 逐状态检查列出具体缺口 |
| 候选已看、操作归属待补 | 查看进度和归属检查分别输出 |
| 原图/裁剪粒度 | 状态归属采用 native 全图依据，角色证据按区域核对 |
| 参数/对象/文件跳变 | 返回具体键、前后值、步骤及建议复查帧 |
| 确认/结果待补 | 记录事实状态与对应疑点，补查后更新步骤 |
| 复核范围与快照 | 检查独立复核登记、本人查看引用、完整状态范围与当前快照 |
| 内容变更 | 原复核转为 stale，提示重新核对 |
| 旧库迁移 | v1/v2 增量到 v3，保留已有索引、查看、步骤与疑点 |
| 完成度 | valid 与 review_complete 分别表达记录完整性和当前审阅条件 |

## 执行与记录

运行 `python -X utf8 -m unittest discover -s scripts/tests -v`，保存实际失败与通过输出。媒体处理复用 FFmpeg、NumPy、Pillow 与 SQLite。原有严格模式 31 项历史回归继续纳入全量测试。各阶段结果与日志见 [validation.md](validation.md)。
