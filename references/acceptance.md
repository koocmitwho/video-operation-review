# 验收设计（实现前定义）

> 本文保留早期验收契约及 31 项回归历史；其中“默认 coverage”已在新版本改为显式严格模式。当前默认分层验收与实施见 [layered-acceptance.md](layered-acceptance.md)。旧用例没有删除，显式选择 coverage/strict 后继续验证同一行为。

这是脚本的可重复验收契约，不是软件操作完整性的证明。测试只在自建短视频和隔离审阅目录中运行。

| 案例 | 可控输入 | 可观察的通过条件 |
|---|---|---|
| 连续重复 | 8 帧无损视频，0–2 相同、3 为单帧小提示、4–5 恢复、6–7 对话框 | 索引/计算各 8 帧；连续相同段映射为 4 个代表；不删除原始索引 |
| 微小短暂变化 | 160×90 画面仅 3×3 像素变化，持续 1 帧 | 保留变化帧、进入前和退出后状态；原因可查询 |
| 时间与尺寸 | 160×90 CFR、426×240 VFR；后者起始 PTS 5 秒，间隔 0.04/0.16/0.28 秒 | 原始 PTS 和尺寸与生成契约一致；不得用帧号除平均帧率代替时间 |
| 中断恢复 | 在计算 3 帧后预算暂停，再运行同一命令；另强制终止子进程 | SQLite 可读；已提交范围可报告；重启只新增缺失计算，保留历史；回放解码另计 |
| 解码失败 | 损坏或截断输入；失败发生于索引或解码 | 保存失败状态、错误日志与最后提交范围；不声称全帧完成 |
| 审阅去重 | 同一原图登记两次，再登记其裁剪 | 事件可有 3 条，独立源帧计数为 1；没有查看登记时仍为 0 |
| 引用校验 | 步骤引用未查看证据、删除/替换证据文件、引用不存在 ID | 校验给出具体错误；生成图片或路径不会使候选完成 |
| 自报边界 | 提交带工具引用的查看登记 | 仅报告登记计数；独立核实计数保持未知；校验不宣称证实查看行为 |
| 缓存身份 | 同目录换视频内容或变更计算参数 | 拒绝混用旧索引，要求另建审阅目录 |
| 局部补查 | 以原始时间选择一个小区间并导出、裁剪 | 帧号/时间/父证据保留；补查不自动计入视觉查看 |
| 可复用交付 | 导入操作及疑点，再导出 | JSON、逐帧 JSONL、Markdown 包含统计、证据和待核对项 |

## 实现计划

**Goal:** 将上述契约做成可移植的 Codex 技能和可执行脚本。

**Architecture:** `review_video.py` 提供命令入口；`vor_media.py` 负责原始时间索引及流式 RGB 解码；`vor_store.py` 负责持久记录、候选选择、证据与校验。SQLite 是单个审阅目录的事实来源；图片只在导出证据时保存。

**Tech Stack:** Python 3.10+、NumPy、Pillow、FFmpeg/ffprobe（支持 `-fps_mode passthrough`）。测试使用标准库 unittest。

**Spec:** 本文件和本次用户给定的六部分要求。

**Global Constraints:** 维护本仓库的技能、脚本及测试；保留输入视频与已有审阅证据。先验收再实现；不设置固定候选数量上限。全部查看登记均需实际图片工具调用，记录校验只证明内部一致。

- [x] 建立 `scripts/tests/test_review.py` 和可控视频生成器；运行 `python -X utf8 -m unittest discover -s scripts/tests -v`，先确认因缺失命令实现失败。
- [x] 实现 `scan` 和 `select`：持久索引、原始 PTS、精确重复段、整体/局部差分、前后邻帧、时间锚点、暂停与恢复。运行对应验收。
- [x] 实现 `extract`、`crop`、`record-view`、`import-records`、`validate`、`status`、`export`：源帧身份不随裁剪改变，缺失/未审阅证据必须被识别。运行全部验收。
- [x] 完成简洁入口和按需参考文档；运行 skill-creator 的 `quick_validate.py`。
- [x] 在隔离输出目录用可控视频完成一次实际图片工具审阅，检查工具记录和最终交付。真实用户录屏未提供时单独标明未试用。

测试和记录应保留真实失败与修复证据，不由摘要替代实际验证。

## 操作遗漏检查增补（先定义后实现）

目标：从只验证已写记录，扩展到主动发现尚未解释的画面状态、步骤状态跳变和过期复核。复用现有解码、索引、证据与 SQLite，不引入媒体处理框架或模型 API。

| 新案例 | 通过条件 |
|---|---|
| 低于所有差分门限的单像素短暂变化 | 默认 coverage 选帧仍保留该连续画面状态；显式 changes 模式遗漏它时 audit 能发现 |
| 步骤区间覆盖整个视频，但中间状态没有对应记录 | audit 仍报告未说明状态，不能靠一个很大的步骤区间冒充完整 |
| 候选全部有查看记录，但操作归属缺失 | 仍未通过遗漏检查，说明看过与解释过是两项要求 |
| 把未查看状态标为无关，或只看了裁剪 | 不算已完成状态说明；必须有该精确重复段原图的查看登记 |
| 步骤前后的同名参数、对象或文件矛盾 | 输出具体键、两个值、相关步骤和补查帧；正确衔接不报此类缺口 |
| 确认或结果未展示 | 保留缺口，不能只把 issue 改为 resolved 就消除结构问题 |
| 审计补查清单入队 | 复用已计算指标，只新增对应帧和前后上下文，不增加查看计数 |
| 完整状态说明和步骤记录 | 可进入独立遗漏复核，仍不等于已证明语义完整 |
| 复核缺失、同一作者冒充独立、复核范围不足 | 严格检查不通过；无独立工具时允许标为 self_review 交付，但不冒充独立复核 |
| 复核后步骤或证据状态发生变化 | 旧复核的内容快照失效，必须重新核对 |
| 旧数据库 | 增量迁移保留已有帧、查看、步骤与疑点；旧记录可继续导出，新增检查列明缺项 |
| 记录与报告 | 导出遗漏审计、未说明范围、状态跳变、复核状态；semantic_completeness_proven 始终为 false |

实施顺序：先运行 `scripts/tests/test_omissions.py` 的失败验收；新增 `scripts/vor_audit.py` 并接入 CLI、导入和导出；补充按需参考文档；运行全部回归、格式校验和有界独立前向试用。真实历史视频不自动重跑。

执行结果：上述增补已完成。16 项遗漏检查回归连同原有 15 项共 31 项通过；实际前向试用保留了素材缺口并正确返回严格检查未完成。详见 [validation.md](validation.md)。
