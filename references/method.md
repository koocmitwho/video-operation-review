# 处理方法与异常边界

需要调整选帧、理解时间戳、恢复中断或解释统计时读本文。

## 索引与源身份

`scan` 接收本地文件，绑定完整文件 SHA-256、字节数和绝对路径。使用第一个视频流 `v:0`；容器声明帧数单列，不作为真实总帧数。ffprobe 逐条输出全部解码帧的信息：0 起始呈现顺序帧号、原始整数 PTS、PTS 秒、best-effort 时间、实际宽高、帧时长、编码关键帧标志；媒体元数据保存 time_base、旋转等信息。保留绝对原始时间，起点可以非零或负值。

正常使用原始 PTS；缺失时将 best-effort 标为推算来源，均缺失则时间为 null，不伪造时间。重复、倒退、缺失时间分别计数。`focus`、`candidates --start/--end` 使用原始时间而非播放器从零计时；先查看索引/候选时间。`frame_no / fps` 不能用于 VFR。

仅完整且无解码错误的 ffprobe 索引才给出 `video_total_frames`，口径是可解码呈现帧。`frame_no` 是该时间线的顺序序号，不能直接当作容器声明的帧槽编号。`full_compute_complete` 仅指此时间线全部计算完成；容器声明与解码计数不一致时，`container_frame_count_mismatch` 为 true，校验和报告明确警告。先核对源包、原始 PTS 和解码日志，不能仅凭数量差异认定丢帧，也不补造帧或查看记录。损坏输入可能无法得知真实总帧数：报告已索引前缀和未知尾部。`-v error` 日志非空时保守标为失败；保存完整日志，不能把丢帧或解码错误当作正常完成。

## 顺序解码与变化计算

FFmpeg 禁止自动旋转，使用 `-copyts`、`-fps_mode passthrough` 和 PPM 管道输出原尺寸 RGB24。不设置固定分辨率、固定 FPS 或帧数。每次只持有相邻图像和差分矩阵；不默认写出全部 PNG。保存数据是每帧一行 SQLite 指标，不是每帧图片。

- **精确重复**：对完整 RGB24 内容和宽高作 SHA-256；连续相同图像共用 `exact_start`。不会跨越变化帧把前后相似状态折叠。这里“相同”是指定解码管线中的 RGB24 相同，不声称原始高位深/色彩数据相同。
- **整体变化**：逐像素取三个通道差的最大绝对值，再对全图平均。
- **局部变化**：全分辨率非重叠方块的平均差，保存最大值及对应矩形；所有方块参与计算。方块默认 32 像素，边缘按实际面积归一。
- **变化像素**：差值不低于 `--pixel-threshold` 的像素数量和比例。原始扫描默认阈值 8；不是 OCR，也不理解操作语义。
- 前后尺寸不同则记录变化边界，不对不匹配数组作差。中途分辨率改变依赖 FFmpeg 输出支持；发现索引/输出尺寸错位或帧数不同即失败，不声称完整支持所有动态尺寸编码。

局部均值会稀释很小的变化。所有模式都保留完整逐帧索引和不同 RGB 状态；显式 coverage 模式还将每个状态送入候选。新默认 layered 只将代表/风险画面送入粗审，未精审状态仍可回查。任何模式都不能恢复压缩后消失、帧间发生或完全被遮挡的动作。鼠标、闪烁、动画和噪声不是自动确认的操作，也不能被脚本自动判为无关。

## 选帧与证据

`select` 默认 `--mode layered`，由 `plan` 建议界面变化簇、稳定段和上下文窗口；读取 [layered-review.md](layered-review.md) 完成人工语义分段、精审及抽查。`--mode coverage` 显式保留每个不同连续状态；`--mode changes` 沿用差分门限初筛，这两个旧选择模式保存 strict 审计模式。任何候选列表都不等于完整操作清单。最终图片候选只按精确连续重复段复用；近似区间合并不改变 requests、exact_start 或源帧身份。编码关键帧标志不作操作语义判断。

重新 `select` 只替换自动选择原因，保留 `focus` 和 `audit --queue` 产生的补查候选、查看记录、步骤和证据。模式、阈值及历史选择写入数据库。不要在未查看的情况下用“跳过/相似”伪造已查看。`audit` 始终从已计算的完整状态索引核对，不依赖候选数或步骤区间的粗略覆盖。

`extract` 通过源帧顺序选择输出，逐张核对与扫描时的完整 RGB 哈希，随后保存 PNG；`crop` 保留父图、坐标和源帧号。文件 SHA-256 用于后来识别丢失或篡改；这些哈希只能验证缓存身份，不证明语义判断或视觉注意力。导出本身不增加查看计数。

大量不连续候选使用平衡的 FFmpeg 选帧表达式，连续帧仍压缩为区间，避免线性表达式过深而解析失败。提早 EOF 分别报告解码器退出/日志错误或缺失目标帧；只有实际像素不匹配才报告图片身份错误，已完成的证据前缀继续保留。

## 恢复、缓存与预算

每个审阅目录仅允许一个写入命令；主代理串行导入子代理文件。数据库事务防止半条记录；默认每计算/索引 100 帧提交，可调。正常异常和 Ctrl+C 尽量提交完整记录并结束 attempt；系统强杀可能留下 `running_or_unfinalized`，它表示未正常结束，也可能是进程仍运行，不自动判为失败。`status` 按数据库实际已提交帧计算范围，未提交工作不冒充完成。

数据库版本 3 增量迁移 v1/v2：增加分层区间、抽查、分层复核、拼图、语言来源表和查看粒度列；旧记录及旧严格模式保留。新库默认 layered；旧库运行 plan 才显式改成 layered。重新计划不覆盖人工区间。未知新版本数据库拒绝打开。普通 validate 通过仍不等于当前模式遗漏门禁通过。

同源同参数重跑 `scan` 复用完整索引与指标。为保证 VFR 和帧身份，未完成扫描恢复时会从头顺序解码并核对已缓存前缀，但不重算其差分；`attempts.decoded_frames` 与 `new_frames` 分开记账。索引中断也需要重新扫描并核对前缀。因此“恢复”不等于零重复解码；源文件哈希也要读取整个文件。候选抽取可能从头解码至最后目标帧，适合按阶段批量抽取，避免反复单张远端定位。

计算参数或 FFmpeg 版本变化拒绝混用旧指标；另建审阅目录。视频内容变化拒绝复用。`select` 的门限可直接重选；改变像素判定门限或方块大小需要新扫描。避免在处理中编辑源视频。

`--max-new-frames` 是用户明确计算预算时可选的暂停点，无默认上限；不能限制已做的全量 ffprobe 索引耗时，也不是模型 token 限额。模型/子代理预算需在实际审阅过程中另外跟踪，没有工具实测时不编造总 token 或节省比例。

当预算恰好到达索引末帧时，继续读取真实 EOF 并检查退出码和错误日志；成功才标记完整，避免只为确认末尾而再回放一次。末帧后的解码错误仍会阻断完成状态。

补查必须有具体疑点和区间；在 issue 的 `attempts` 写下新增证据与是否推进结论。当同一缺口重复补查仍无新增有效证据，转为 unresolved/blocked，并说明被遮挡、未展示、画质不足或缺少上下文。可说明下一步需要何种材料，不自动扩大到整段重审。
