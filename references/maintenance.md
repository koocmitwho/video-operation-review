# 开发来源与发布检查

本项目采用一份主开发目录。当前维护工作以 `video-operation-review` 为主，`video-operation-review-github` 是用于 Git 发布的副本；在其他机器上可直接把自己的 Git checkout 作为主开发目录。所有脚本、测试和中英文说明在选定的主目录修改，发布副本不另行开发。

发布准备顺序：

1. 确认两份目录的现有改动，保留快照；有差异时逐项合并，不用目录覆盖代替合并。
2. 在主目录运行 `python -X utf8 -m unittest discover -s scripts/tests -v`。修改行为先保留失败用例，再改实现。
3. 先更新中文说明，再据此同步英文；验证结果注明日期、环境与实测边界。
4. 把核对后的发布文件复制到发布副本，保留目标的 `.git` 和已有工作；遇到目标独有改动先合回主目录。原始视频、工作库、会话日志和含个人路径的开发记录留在项目外。
5. 运行以下只读检查；返回 0 才表示两份交付文件内容一致。返回 1 会列出修改、缺失与多余文件，返回 2 表示路径或源项目不正确。检查器不会覆盖、删除或同步文件。

```text
python scripts/check_release.py --target ../video-operation-review-github
```

可用 `--source` 显式指定主目录。只忽略 `.git`（目录或 worktree 元数据文件）、Python 缓存和虚拟环境；其他额外文件会被报告，不能在发布核对中悄悄丢掉。读取/枚举错误及非忽略目录的符号链接或 Windows junction 返回 2，不把未完整检查的目录标为一致。比较按文件字节 SHA-256 进行。

GitHub Actions 配置对 Windows / Ubuntu 和 Python 3.10 / 3.12 执行依赖诊断及完整测试。配置存在不代表远端已运行通过，应查看对应提交的实际 CI 结果。提交和公开发布由维护者按当前授权执行。

历史验证 JSON / 日志保留日期，新验证另存文件，避免把旧结果当作当前状态。代码约束只验证记录一致性，不证明真实看图或语义完整。
