# 审阅负担与记录纠错：下一轮计划

日期：2026-10-07。状态：规划建议；本轮不启动实现、提交或发布。

> 执行补记：上句保留最初规划轮的范围。随后用户在新对话授权实施与测试，四阶段已执行；同库纠错保留，分组试验按停止条件撤回。结果、限制和未发布边界见[2026-10-07 验收](../../../validation/next-iteration-20261007.md)。

> 执行者按独立工作项推进，先复现、再写失败测试、再做最小修改和独立复核。可使用现有子代理协作工具；不能把缺失的外部工作流技能作为强制依赖。

**目标：**在关键操作与未知边界不退化的条件下，减少代理反复看图、手工记账和纠错重做的负担。

**架构方向：**复用现有全帧索引、分层区间、查看记录、审计和导出。将“候选生成”“何种证据足以完成相应审阅”“误设记录怎样更正”拆开验证；每次只接受一个有独立验收结果的改动。

**技术范围：**现有 Python、SQLite、NumPy、Pillow、FFmpeg；第一轮不引入新的运行依赖。

**依据：**[RC.4范围](../../../references/release-rc4.md)、[公开案例结果](../../../examples/open-cases/results.json)、[分层审阅规则](../../../references/layered-review.md)、[现有验收](../../../references/layered-acceptance.md)。本文件是阶段路线图；会改变完成标准的方案须先形成具体证据规则，再进入实现。

## 当前基线

- 已发布0.1.0-rc.4，提交45ea1511021dc41937a7cdeddb2af8f06939f200。本次查询无开放Issue/PR。RC.4更新证据和试用材料，没有改变运行算法。
- Inkscape：1903个计算帧、394个建议段；其中393段来自`layout/control surface change`分支，291段只有一帧。这个统计定位了触发分支，没有证明具体是缩放、鼠标还是其他变化导致。
- 当前585候选中78个达到原图查看要求，507个待原图；原图源帧83、概览源帧517，去重590。不能把概览登记当作原图完成。
- 概览代表帧进入统一候选集合；候选完成统一要求`native + full`；分层模式也把全部候选完成与独立审计共同作为完成条件。因此候选生成和门禁设计必须分开检查。
- 正则案例误把片头静态条件单列为操作后，用保留旧库的新尝试修正；同ID更新已存在，但没有公开的步骤退休入口。
- 21秒是单次代理照做的任务阶段，不是完整视频审阅耗时；没有同条件省时对照和真人验收。Q01重启生效、Q02录屏保存是来源缺口。

## 全局约束

1. 原始素材、源SHA、PTS、RGB/资产身份、查看记录及历史失败保留。
2. `valid`继续表示记录和证据完整性；旧严格模式的要求不变。
3. 不为让某个案例通过而取消检查、删除未知、退役未解决异常或把概览记作原图。
4. 新证据规则若影响完成条件，须明确适用模式、兼容方式和旧结果解释；旧账本不得被静默重评为完成。
5. 结果分别报告工程流程、特定任务可用性、语义证据与耗时；没有数据的项写未测。
6. 主目录维护，验证后按现有流程同步发布副本；保留已有未提交/未跟踪文件。后续提交与发布按当时授权执行。

## 第一阶段：定位负担并明确证据规则（建议0.5–1个工作日）

**检查文件：**`scripts/vor_layers.py`、`scripts/vor_store.py`、`scripts/vor_layer_audit.py`；已有`test_layers.py`、`test_review.py`和`make_layered_fixture.py`。

- [ ] 冻结RC.4、现有三个源视频哈希及账本副本，分开记录环境准备、全帧计算、看图、登记/纠错、独立复核和导出。
- [ ] 对已有索引只读归因，分别统计变化面积条件、全局变化量条件及二者重叠的触发次数，定位291个单帧段。保留完整事件清单。
- [ ] 在高密度段核对“明确操作、构图变化、悬停/其他、无法判断”，预先冻结关键检查点。只使用目前有证据的事实，模型输出不作为独立人标。
- [ ] 用三个已有风格的受控小例说明证据要求：只有上下文变化；细小参数/确认动作；风险抽样发现异常后展开。写出概览、原图/裁剪、独立复核各自负责什么。
- [ ] 比较两个改进方向：仅减少误拆分、保留当前门禁；或进一步明确分层请求的证据职责。第一种优先；第二种须单独评审，不能与阈值调整混在一起。

**交付：**一份成本/边界归因表、一份证据要求表、一项最小候选策略建议。

**退出条件：**能解释哪些请求来自哪个条件、哪些确实需要原图；尚无事实支持的归因继续列为假设。本阶段不修改完成公式，不以Inkscape必须变成完成作为目标。

## 第二阶段：让误设步骤可以在原库中纠正（建议1–2个工作日）

**拟涉及文件：**`scripts/vor_store.py`、`scripts/vor_record_contract.py`、`scripts/vor_layers.py`、`scripts/vor_layer_audit.py`；必要的导出适配只限`vor_export.py`/`vor_report.py`。文档更新`references/records.md`、`references/examples.md`。

**测试位置：**`scripts/tests/test_record_contract.py`、`test_layers.py`、`test_export_generation.py`。

- [ ] 用正则案例的最小副本重现“静态前提误设为步骤，现有公开接口无法退休该记录”的流程，保存失败。
- [ ] 先写失败测试，固定以下行为：带理由更正误设步骤；保留原记录和历史；关联区间/疑点必须有明确处理；失败时整批回滚。
- [ ] 在现有导入事务中增加最小的步骤退休/替代入口。只解决误设步骤，避免扩成通用撤销或版本控制系统。
- [ ] 使受影响的旧复核快照失效，导出展示当前有效步骤，同时能追溯原记录；不能借退休关闭或抹掉未解决异常。
- [ ] 在同一账本内完成案例纠正，重新运行审计、独立复核和导出。

**验收：**不重建整库也能纠正此实测问题；源文件、原图和查看记录不变；无孤儿引用；非法更正原子回滚；旧审阅结论不能继续冒充当前有效。该项可独立交付，不依赖候选算法优化。

## 第三阶段：只实现一项有证据支持的候选优化（建议1–2个工作日）

**拟涉及文件：**主要为`scripts/vor_layers.py`、`scripts/tests/test_layers.py`及`make_layered_fixture.py`。第一阶段若表明必须调整证据职责，则另列审计/兼容性设计，不顺带改`review_complete`。

- [ ] 从第一阶段选出一个最小策略，固定旧策略与候选策略的输入、参数、检查点和测量口径。
- [ ] 先写能暴露误拆分的失败用例，并保留单帧菜单、临时输入、取消、重输、确认、结果变化、文件交接和异常展开用例。
- [ ] 实施最小分组修正；保存全量底层状态和时间身份。任何近似合并必须可追溯并有必要的风险复查。
- [ ] 在原三个案例上比较候选数量、实际原图/概览输入、登记/纠错次数、分阶段耗时。分别展示变化，不把任一计数下降当作语义提升。

**验收：**冻结的关键事实没有新增遗漏或错误成功结论；小参数和短暂菜单保护通过；错误/未知保留；工作量下降有可查明细。收益若只来自放宽门禁、删除候选记录或减少检查，则不合入。

**停止条件：**策略没有明确收益、漏掉关键状态或需要新增大型依赖时，保留实验结论并回到RC.4策略，不继续堆复杂度。

## 第四阶段：新上下文对照与更完整案例（建议1–2个工作日）

- [ ] 增加至少一个此前未参与开发、许可明确、含初始准备与可见结束结果的完整录屏。优先另一来源和不同操作链，建议2–5分钟；先检查是否存在可复核参考材料。
- [ ] 新上下文代理从原视频生成报告，另一代理只拿报告照做；预期答案在第一次结果冻结后才提供。真实输入、输出及不确定项分别保存。
- [ ] 对RC.4与候选版做至少3次条件一致的配对运行，固定模型、工具、输入及给出的任务范围；逐次记录，不让同一参与代理带着上一次答案进入另一组。
- [ ] 对比关键错误、漏项、求助、重建次数、原图/概览工作量和各阶段历时。计数变化与时间波动分开；没有稳定的耗时改善就不宣称省时。
- [ ] 一般真人可靠性继续单列，需要真实参与者；代理对照不能改写为真人结果。

**发布条件：**受控回归和真实案例都没有新增关键错误；变更收益与限制明确；本地及对应提交远端矩阵通过；发行包下载后验收。每个小改可独立验收，未成立的候选策略不并入发行。

## 检查方式与执行顺序

现有全套工程回归入口：

```text
python -X utf8 -m unittest discover -s scripts/tests -v
```

实施时先跑相应定向失败测试，修复后跑受影响测试，再跑完整回归；不反复重跑无变化的检查。原有保护包括`test_review_complete_requires_candidates_and_current_gate`、`test_overview_sheet_is_not_native_fine_evidence_and_views_dedupe`、`test_sample_cannot_be_filled_with_unrelated_or_overview_only_assets`、`test_retiring_or_shrinking_interval_cannot_erase_sample_anomaly`。

**建议顺序：先做第一阶段与第二阶段；第三阶段由诊断结果决定具体策略；最后做第四阶段。**总量初估约4–7个工程工作日，不含素材/真人参与等待，不是完成承诺。

执行方式建议分任务子代理实施、另一个代理按需求与代码分别复核；也可由主线程顺序实施并独立复核。两种方式都不沿用已知答案作为新测试的独立真值。

OCR/ASR扩展、云服务、完整评测平台、交互式复核界面和工作流依赖升级分别排队，等这轮成本与纠错问题有结果后再评估。当前两个来源缺口不靠增加模型或补看数量关闭。
